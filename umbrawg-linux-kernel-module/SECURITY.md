# Безопасность UmbraWG (kernel module)

## Сообщение об уязвимости

Не создавайте публичный issue. Отправьте описание на email сопровождающего
(см. `git log` / контакты репозитория) или через приватный канал GitHub
(Security → Report a vulnerability). В письме укажите:

- затронутую версию/коммит;
- шаги воспроизведения;
- влияние (локальное/удалённое, повышение привилегий, DoS);
- при наличии — минимальный PoC.

## Что считается уязвимостью

- Обход аутентификации/шифрования, раскрытие ключей или трафика.
- Повышение привилегий через модуль (некорректные проверки прав, переполнения).
- Удалённый DoS (краш ядра, бесконечные циклы, исчерпание памяти).
- Некорректная обработка netlink-ввода, приводящая к OOB-доступу.

Не считаются уязвимостями: проблемы производительности, stylistic issues, ошибки сборки.

## Особенности ядра и привилегий

- Модуль работает в пространстве ядра с полными привилегиями; любая ошибка
  в обработке сетевого ввода критична.
- Netlink-команды требуют `CAP_NET_ADMIN`; убедитесь, что доступ к ним
  ограничен доверенными пользователями.
- Отладочный вывод (`CONFIG_UMBRAWG_DEBUG`) не должен включаться в продакшене:
  он может раскрывать чувствительные данные.

## Сроки ответа

- Подтверждение получения: до 7 дней.
- Первичная оценка: до 14 дней.
- Исправление критических уязвимостей: по возможности в течение 30 дней.
- Публичное раскрытие — после выпуска исправления, согласованно с автором.
