# BBRv3 и FEC: состояние интеграции

Ветка: `feature/bbrv3-fec`. Master и релиз `v0.1.0` не затронуты:
по умолчанию `bbr=off`, `fec=off`, накладных расходов нет.

## Что уже работает

- Протокольный extension внутри AEAD: CAPS, ACK с 64-битным bitmap,
  FEC-шарды; handshake и transport header не изменены.
- Обмен CAPS после рукопожатия, ACK каждые 2 пакета/1 мс, сброс
  feedback при смене keypair.
- BBRv3-контроллер (state machine, BtlBw/RTprop, Startup/Drain/
  ProbeBw/ProbeRtt, inflight_hi/lo) получает ACK и длины пакетов.
- Reed-Solomon FEC: блоки k+m, GF(256), восстановление любых m стираний,
  adaptive/fixed режимы, частичные блоки без parity.
- UAPI-поля `bbr=`, `fec=` и снимок `get=1`; временно включение через
  env `UMBRAWG_BBR`, `UMBRAWG_FEC`, `UMBRAWG_FEC_SHARD`,
  `UMBRAWG_ACK_INTERVAL`.
- При включённом FEC TUN GSO и socket GSO отключаются: иначе netem
  теряет целый GSO-агрегат, и FEC не может восстановить отдельные шарды.

## Замеры (veth 9000, 3c, один поток)

| Сценарий | Результат |
|---|---|
| UDP 200M, loss 2%, FEC off | 196.1 Мбит/с, потери **1.967%** |
| UDP 200M, loss 2%, FEC 10:2 | 199.7 Мбит/с, потери **0.036%** |
| TCP, loss 2%, FEC off | 213 Мбит/с |
| TCP, loss 2%, FEC 10:2 | 38 Мбит/с |
| TCP, без потерь, FEC 10:2 | 899 Мбит/с (off: ~3.3 Гбит/с) |
| TCP, rate 200m/10ms, BBR off | 180 Мбит/с |
| TCP, rate 200m/10ms, BBR on | 180 Мбит/с (pacing почти не влияет) |
| UDP 200M, rate 100m, BBR off | 92 Мбит/с, потери 52% |
| UDP 200M, rate 100m, BBR on | 22 Мбит/с, потери 88% |

## Выводы и ограничения

- FEC даёт почти полное восстановление потерь для UDP и не мешает
  трафику без потерь, когда выключен.
- Для TCP на veth (RTT ~0.2 мс) FEC с k=10 увеличивает задержку
  восстановления выше RTT: TCP успевает войти в recovery раньше, чем
  приходит блок. На реальном WAN нужен отдельный замер; до этого FEC
  рекомендуется для UDP/ICMP и включается явно.
- Отключение GSO при FEC снижает чистую скорость TCP (3.3 → 0.9 Гбит/с).
  Нужен вариант FEC поверх транспортных пакетов без потери GSO
  (отдельные GSO-группы на шард или FEC по inner-сегментам).
- BBR pacing в текущем виде экспериментальный: ACK/оценка работают, но
  пейсер на малых батчах занижает скорость. `bbr=on` пока не
  рекомендуется; нужен батчевый token bucket и cwnd-учёт в отправке.
- Для включения через конфиг/netlink нужны ключи `BBR`/`FEC` в
  `umbrawg-config`/`umbrawg-ctl` (UAPI-поля уже есть); netlink-атрибуты
  появятся вместе с портом в ядро.

## Следующие шаги

1. Батчевый пейсер BBR и учёт cwnd в `send_run`; тест на rate/loss.
2. FEC для TCP: меньший k/задержка, GSO-совместимая упаковка шардов.
3. Адаптивный FEC по ACK-loss с гистерезисом.
4. Конфиг/CLI/netlink и порт в ядро.
