# BBRv3 и FEC: состояние интеграции

Ветка: `feature/bbrv3-fec`. Master и релиз `v0.1.0` не затронуты:
по умолчанию `bbr=off`, `fec=off`, накладных расходов нет.

## FEC

- Reed-Solomon GF(256), блоки `k+m`, восстановление любых `m` стираний.
- Режимы: `off`, `fixed K:M`, `adaptive`.
- `adaptive`: FEC выключен на чистом канале; включается при loss > 1%
  (окно 256 пакетов, после 1024 пакетов прогрева) и выключается после
  5 секунд с loss < 0.2%.
- TUN GSO остаётся включённым. Внешние GSO-группы при активном FEC
  ограничены `m` шардами, чтобы потеря GSO-агрегата не убивала больше
  `m` шардов; ограничение применяется к живым сокетам динамически.
- FEC работает над внешними IP-пакетами и не различает TCP/UDP/ICMP.

### Замеры (veth 9000, 3c, один поток)

| Сценарий | Скорость | Потери/результат |
|---|---:|---|
| TCP clean, FEC off | 3267–3493 Мбит/с | — |
| TCP clean, FEC adaptive (не активен) | **3330 Мбит/с** | без регрессии |
| UDP 200M loss 2%, FEC off | 196.1 Мбит/с | 1.967% |
| UDP 200M loss 2%, FEC fixed 10:2 | 199.7 Мбит/с | **0.036%** |
| UDP 200M loss 2%, FEC adaptive 2:1 | 198.9 Мбит/с | **0.316%** |
| TCP loss 2%, FEC fixed 2:1 | **457 Мбит/с** | лучше TCP без FEC (213) |
| TCP loss 2%, FEC adaptive 2:1 | **440 Мбит/с** | лучше TCP без FEC |
| TCP clean, FEC fixed 10:2 | 1870 Мбит/с | цена fixed-режима |
| TCP loss 2%, FEC fixed 10:2 | 30 Мбит/с | большой блок не успевает |

## BBRv3

- ACK-based state machine (BtlBw/RTprop, Startup/ProbeBw/ProbeRtt,
  inflight_hi/lo) интегрирован; DRAIN для туннеля пропускается, потому
  что очередь приложения находится снаружи.
- Пейсер работает на батчах; TUN-пакеты накапливаются между чтениями,
  мелкие батчи не спят.
- BBR имеет bounded per-peer очередь (1024 пакета / 4 МиБ), чтобы не
  блокировать воркер на ожидании ACK.
- Пейсер применяется к многопакетным батчам, не к каждому пакету;
  мелкие батчи не спят, долг копится в token bucket.
- UDP 200M на линке 100M: off 92.1 Мбит/с / 52.1% потерь, on
  91.8 Мбит/с / **45.4%** — скорость не падает, потери ниже.
- RTT под нагрузкой: off ~75 мс, on ~113 мс — очередь BBR/TUN ещё
  добавляет задержку; приоритет малых/управляющих пакетов нужен.
- TCP clean: on 3840 Мбит/с, off 3267–3493 — регрессии нет.
- `bbr=on` пока экспериментальный; жёсткий cwnd-лимит не включён,
  используется pacing + bounded queue.

## Ограничения

- Fixed FEC для TCP на малом RTT может ухудшать throughput: блок
  собирается дольше, чем TCP успевает войти в recovery. Для TCP
  использовать adaptive (на чистом канале не активен), либо ждать
  уменьшения `k`/задержки блока.
- GSO-группа при FEC ограничена `m`; это снижает syscall-батчинг, но
  сохраняет восстановление.
- Конфиг/CLI/netlink-ключи `BBR`/`FEC` ещё не добавлены в tools;
  временно env `UMBRAWG_BBR`, `UMBRAWG_FEC`, `UMBRAWG_FEC_SHARD`,
  `UMBRAWG_ACK_INTERVAL`. UAPI-поля уже есть.
- Порт в ядро не начат.

## Следующие шаги

1. Батчевый BBR-пейсер (token bucket на батч, cwnd/inflight).
2. Адаптивный FEC для TCP: меньший `k`, block deadline < RTT.
3. Конфиг/CLI/netlink, затем порт в ядро.
4. Матрица против amneziawg-go на loss/rate.
